# ARCHITECTURE: Docker Integration

| Field       | Value |
|-------------|-------|
| Version     | 20260512 V1 |
| Description | Optional per-project Dockerfile generation and container lifecycle management via a conform_dockerize function. |

Docker support is opt-in and non-invasive. The conformance layer generates a `Dockerfile` for a project; the project's own code does not change. GAME's ops engine detects docker-enabled projects and routes start/stop commands through the Docker CLI instead of direct subprocess invocation.

---

## Design Principles

- **Zero project code changes.** The Dockerfile is the only artifact added. `bin/start.sh`, `common.sh`, and `common.py` remain unchanged inside the container.
- **Docker is optional.** Controlled by `docker_enabled: true` in METADATA.md (default: absent/false).
- **Conform generates; GAME operates.** `conform_dockerize` (Prototyper) writes the Dockerfile. GAME's scanner detects it; ops.py routes lifecycle calls accordingly.
- **Port mapping is explicit.** The container port equals METADATA.md `port:`. The host-published port defaults to the same value but is overridable via `docker_host_port:` in METADATA.md.

---

## New METADATA.md Fields

| Field | Default | Description |
|-------|---------|-------------|
| `docker_enabled` | absent (false) | Set to `true` to generate and use a Dockerfile. |
| `docker_host_port` | same as `port:` | Host port to publish the container port on. |
| `docker_base_image` | auto-selected by stack | Override the base image (e.g. `python:3.12-slim`). |
| `docker_extra_packages` | none | Space-separated apt packages to install in the image. |

## `conform_dockerize` Function

**Location:** `bin/ProjectInitialize.sh` (new step) + standalone `bin/dockerize.sh <project>` for manual re-generation.

**Trigger:**
- Automatically called by `ProjectInitialize.sh` if `docker_enabled: true` in METADATA.md.
- Run manually: `bash bin/dockerize.sh <ProjectName>` to regenerate Dockerfile after spec changes.

**Input sources:**

| Source | Fields used |
|--------|-------------|
| `METADATA.md` | `name`, `stack`, `port`, `health`, `docker_base_image`, `docker_extra_packages` |
| `AGENTS.md → ## Endpoints` | Exposed HTTP routes (informational only — validates EXPOSE port) |
| `AGENTS.md → ## Capabilities` | CLI entry points (used to confirm bin/ scripts exist) |
| `requirements.txt` / `pyproject.toml` | Detected to select install command |

**Base image selection (auto, overridable):**

| Stack keyword | Default base image |
|--------------|-------------------|
| Python / Flask / Django | `python:3.12-slim` |
| Node / Next / React | `node:20-slim` |
| Ruby / Rails | `ruby:3.3-slim` |
| (none matched) | `ubuntu:22.04` |

**Generated Dockerfile structure:**

```dockerfile
# Generated by conform_dockerize — do not edit manually.
# Regenerate: bash bin/dockerize.sh <ProjectName>

FROM <base_image>

WORKDIR /app

# Install system packages
RUN apt-get update && apt-get install -y --no-install-recommends \
    bash curl <docker_extra_packages> \
    && rm -rf /var/lib/apt/lists/*

# Install Python dependencies (Python stack only)
COPY requirements.txt* pyproject.toml* ./
RUN pip install --no-cache-dir -r requirements.txt   # or: pip install -e .

# Copy project files
COPY . .

# Ensure scripts are executable
RUN chmod +x bin/*.sh 2>/dev/null || true

EXPOSE <port>

# GAME health check (uses METADATA health endpoint)
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
  CMD curl -f http://localhost:<port><health_path> || exit 1

CMD ["bash", "bin/start.sh"]
```

**`.dockerignore` (also generated):**

```
.venv/
venv/
__pycache__/
*.pyc
.env
.secrets
logs/
data/
archive/
docs/
*.log
```

## GAME Scanner Changes

`scanner.py` — during `_scan_project()`:

1. Check `docker_enabled` field in METADATA.md.
2. Check `Dockerfile` exists at project root.
3. If both true: set `projects.docker_enabled = 1`, `projects.docker_host_port` in DB.
4. New DB columns: `docker_enabled INTEGER DEFAULT 0`, `docker_host_port INTEGER`, `docker_image_name TEXT`.

Image naming convention: `game-{project_name}:latest`

---

## GAME Ops Engine Changes (`ops.py`)

When `docker_enabled = 1` for a project, lifecycle commands route through Docker CLI instead of direct subprocess:

| Operation | Current (subprocess) | Docker path |
|-----------|---------------------|-------------|
| Start | `Popen(bin/start.sh)` | `docker run -d --name game-{name} -p {host_port}:{port} -v {project}/logs:/app/logs {image}` |
| Stop | `os.killpg(pgid, SIGTERM)` | `docker stop game-{name}` |
| Status | PID exists in `/proc` | `docker inspect --format='{{.State.Status}}' game-{name}` |
| Logs | Read `logs/*.log` from filesystem | `docker logs --tail 200 game-{name}` (also available via mounted volume) |
| Build | — | `docker build -t game-{name}:latest {project_path}` |

Log volume mount (`-v {project}/logs:/app/logs`) ensures GAME's log ingestor continues to read logs from the host filesystem path without change.

## Port Mapping

```
METADATA.md port: 5010  →  container EXPOSE 5010
METADATA.md docker_host_port: 5010  →  host -p 5010:5010

# Override example:
docker_host_port: 15010  →  host -p 15010:5010
```

Health checks use `localhost:{docker_host_port}` when docker_enabled.

---

## Security Isolation

Each conformed+dockerized project runs in its own container:
- **Filesystem:** container root is isolated; only `logs/` is volume-mounted to host.
- **Network:** containers use Docker's default bridge network; no inter-container communication unless explicitly configured.
- **Process:** container PID namespace is isolated from host.
- **Environment:** `.env` passed via `--env-file` at container start (never baked into image).

`.env` mount: `--env-file {project_path}/.env` (passed at `docker run` time, never COPY'd into image).

---

## Lifecycle State Machine (Docker path)

```
UNBUILT → (docker build) → BUILT → (docker run) → RUNNING → (docker stop) → STOPPED
                                                            → (crash)      → EXITED
```

GAME tracks `docker_image_built_at` in the projects table. If Dockerfile is newer than last build timestamp, GAME shows "Rebuild needed" in the Docker screen.

## Open Questions

- Should `bin/dockerize.sh` be added to the Prototyper toolchain, or should conform_dockerize logic live entirely inside `ProjectInitialize.sh`? Leaning toward standalone script so it can be rerun independently.
- Should `.env` be mounted read-only or injected as `--env-file`? `--env-file` avoids mounting a secret file as a volume — preferred.
- For Python uv-based projects (pyproject.toml), should the Dockerfile use `pip install -e .` or `uv pip install`? Need to decide if uv should be in the base image.
- Should `docker_enabled` default to `false` (opt-in) or be auto-detected (opt-out)? Decision: opt-in.
- Multi-worker projects (Flask + Celery worker): single Dockerfile or compose file? Deferred — V1 is single-process only.
